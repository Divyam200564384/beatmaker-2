# Beatmaker 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Beatmaker 2.0, a browser music studio with real sampled instruments. It has two modes. Free play opens every tool. Learn mode is a 15-level game that unlocks tools one at a time.

**Architecture:**
- Pure modules (`music/`, `song/`, `learn/`) hold all music rules, the song data, undo, the share-link codec and the level goal checks. They are fully unit-tested.
- `audio/` wraps smplr. It covers instrument and kit loading, the mixer, a look-ahead clock and offline WAV rendering. The scheduler asks `notesAt(song, step)` what to play.
- React components render one studio. Learn mode reuses that studio through a "lens" that hides tools.

**Tech Stack:**
- React 18.3, Vite 5.4, plain CSS with tokens
- smplr 1.1.0 (MIT): Soundfont, SplendidGrandPiano, DrumMachine, Sampler, Reverb, renderOffline
- Vitest 2, Testing Library, jsdom, and playwright-core for browser checks

**Spec:** `docs/superpowers/specs/2026-10-21-beatmaker-2-design.md`. Read it before any task.

## Review Focus

1. **Background tab or throttled timers.** When the tab comes back, the clock must resync. It must not fire dozens of stale steps at once (Task 7 test `resyncs instead of bursting`).
2. **Tempo change while playing.** The next step lands one *new* step-length after the previous one, with no gap or double hit (Task 7 test `tempo change applies from next step`).
3. **Instrument or kit switch while playing, or a failed load.** The old instrument keeps playing until the new one is ready. A failure keeps the old one and reports an error. Two fast switches never leave two instruments sounding (Task 7 tests `switch keeps old until ready`, `stale load is discarded`).
4. **Bad, old or truncated share links,** and links with out-of-range numbers. These load the default song with the "Couldn't read that song link" message and never throw (Task 4 tests).
5. **Play tapped twice while instruments load.** Only one AudioContext and one load per layer (Task 7 test `double start creates one context`).

### Task 2: Music theory and Euclidean rhythm

**Files:**
- Create: `src/music/theory.js`, `src/music/euclid.js`
- Test: `src/music/theory.test.js`, `src/music/euclid.test.js`

**Interfaces:**
- `NOTE_NAMES = ["C","C#","D","D#","E","F","F#","G","G#","A","A#","B"]`
- `DEGREES = ["I","ii","iii","IV","V","vi","Imaj7","IVmaj7"]`. The order is fixed, because the codec stores the index.
- `FEELINGS = { I:"home, happy", ii:"soft, gentle", iii:"thoughtful", IV:"warm, open", V:"wants to go home", vi:"sad, emotional", Imaj7:"dreamy home", IVmaj7:"floaty, soft" }`
- `NEXT = { I:["V","vi","IV"], ii:["V","iii"], iii:["vi","IV"], IV:["V","I","ii"], V:["I","vi","iii"], vi:["IV","V","ii"], Imaj7:["IVmaj7","vi"], IVmaj7:["iii","Imaj7","V"] }`
- `chordName(degree, key): string`. Returns the root name, plus `"m"` for ii/iii/vi and `"maj7"` for the maj7 degrees. Examples: (`"vi"`,0)→`"Am"`; (`"IVmaj7"`,2)→`"Gmaj7"`.
- `chordNotes(degree, key): number[]`. Intervals above the key root:
  - I `[0,4,7]`, ii `[2,5,9]`, iii `[4,7,11]`, IV `[5,9,12]`, V `[7,11,14]`, vi `[9,12,16]`, Imaj7 `[0,4,7,11]`, IVmaj7 `[5,9,12,16]`.
  - Each note (60 + key + interval) is folded by octaves into **[55, 68)**, then the result is sorted ascending.
- `chordRoot(degree, key): number`. The bass root in **[36, 48)**.
- `scaleNotesBetween(lo, hi, key): number[]`. Major-scale MIDI notes in `[lo, hi]`, used by the walking bass.
- `melodyRows(key): number[11]`. Bottom row first. Base = `60 + (key <= 6 ? key : key - 12)`. Offsets `[0,2,4,7,9,12,14,16,19,21,24]`.
- `euclid(hits: 0..16, steps: 16, shift: 0..15): boolean[]`. Index `i` is on when `((i - shift + steps) % steps) * hits % steps < hits`.

### Task 4: Bass, arrangement and share codec

**Files:**
- Create: `src/music/bass.js`, `src/music/arrange.js`, `src/song/codec.js`
- Test: `src/music/bass.test.js`, `src/music/arrange.test.js`, `src/song/codec.test.js`

**Interfaces:**
- Consumes: Task 2 theory and Task 3 song shape.
- `bassNotesForBar(song, bar): {step, note, steps}[]`.
  - The root `r` is `chordRoot(prog[bar], key)`. If `prog[bar]` is null, return `[]`.
  - **kick:** one `{step, note:r, steps:2}` per kick-pattern hit.
  - **long:** `[{0, r, 15.5}]`.
  - **bounce:** even steps: `r` when `step%4==0`, `r+12` when `step%4==2`; steps 1.5.
  - **walking:** quarter notes at 0,4,8,12: `[r, s1, s2, a]`. Here `s1` and `s2` are the 1st and 2nd major-scale notes above `r`. `a` is the scale note directly below the next bar's root, where the next bar wraps from bar 3 to bar 0. Use the next root octave that's closest to `s2`. If the next chord is null, `a = r`. Each note has steps 3.5.
  - **off:** `[]`.
- `notesAt(song, step): Note[]`, where `Note = { layer, note: number|ringId, velocity, steps, offset? }`. `offset` is in seconds.
  - **Drums:** for each ring with `pattern[step%16]`, return `{layer:"drums", note: ring, velocity: ring==="hat"?70:110, steps:1}`.
  - **Chords** (`prog[bar]` not null):
    - hold: at s=0, each chord note with steps 15.5, velocity 65.
    - strum: at s=0 and s=8, each note `i` of the chord with `offset: i*0.025`, steps 7.5, velocity 70.
    - pulse: at s∈{0,4,8,12}, steps 2, velocity 72.
  - **Bass:** the entries of `bassNotesForBar` where `step === s`, velocity 105.
  - **Melody:** on even steps, col = step/2. A cell with `row ≥ 0` starts a note unless `tie && cells[col-1].row === row`. Its duration is `2 × (1 + number of following cells with tie and the same row)`, with no wrap past col 31. Velocity 95, and the note is `melodyRows(key)[row]`.
- `encodeSong(song): string` and `decodeSong(str): song`.
  - Bit-packed, then URL-safe base64 (`-_`, no padding).
  - Field order: version=1 (8 bits); tempo-70 (7); key (4); kit index in `KITS` (4); perc index in `["openhat","tom","cowbell","rim"]` (2).
  - Then for each ring in order kick, snare, hat, perc: hits (5), shift (4), pattern (16).
  - Then prog ×4 (4 bits each: DEGREES index 0–7, with 15 = null); rhythm index in `["hold","strum","pulse"]` (2); bass style index in `["kick","long","bounce","walking","off"]` (3).
  - Then melody ×32: row+1 (4 bits, 0 = empty), tie (1).
  - Then the instrument index in `INSTRUMENTS` (8) for chords, bass and melody.
  - Then mix for drums, chords, bass and melody: volume (7), mute (1), solo (1), space (7).
- `decodeSong` throws `Error("bad song")` when:
  - the version isn't 1, or the string is too short;
  - a character is invalid;
  - any index is out of range (kit ≥ 10, instrument ≥ 129, prog value 8–14, perc, rhythm or style past the end);
  - any decoded number is out of range (tempo > 140, volume > 100, hits > 16).

    - Creates the AudioContext, mixer and one `Reverb` on the first call only.
    - Loads the kit and the three instruments if they're missing.
    - Then starts the clock.
    - A second call while a start is pending returns the same promise.
  - **`stop()`:** stops the clock and calls `inst.stop()` on every layer.

    - Stores the song and calls `mixer.apply`.

  - **`preview(layer, note)`:** plays one note now, for palette and drawing feedback.
  - **`isPlaying()`.**
  - **Scheduling:**
    - Each clock step calls `notesAt(song, step)`.
    - Drums play `{note: ringSample[ring]}`. The ring sample map is computed once per kit/perc choice with `pickRingSample`.
    - Other layers play `{note, time: t + (offset ?? 0), duration: steps*stepDur, velocity}`.
    - The engine then calls `onStep(step)` via `setTimeout` at audio time.
- **`renderSongWav(song): Promise<Blob>`:**
  - Uses `renderOffline(async ctx => {…}, {duration: 2*loopSec + 2, sampleRate: 44100, channels: 2})`.
  - Inside, it loads the kit and instruments with `loaders` and schedules every step of 2 loops through `notesAt`.
